[010] BeeexAPI – IoT Data Collection & Visualization Platform

Paweł Zięba August 31, 2026

BeeexAPI is an IoT application designed to collect, store, process, and visualize measurement data from IoT devices.

The project was created to explore the complete data flow between an IoT device and a server application, from sending measurements over the network, through storing them in a time-series database, to real-time communication with a web-based user interface.

The system consists of a Python/Flask backend, InfluxDB database, WebSocket communication layer, web interface, and a test client simulating an IoT device.

System Architecture

The application is divided into several independent components:

• IoT device / test client – generates measurement data and sends it to the server
• Flask server – provides HTTP endpoints and handles WebSocket connections
• InfluxDB – stores time-series measurement data
• WebSocket processing layer – handles requests from connected clients
• Web interface – allows users to visualize and analyze collected data

This architecture separates data acquisition, storage, processing, and visualization into dedicated parts of the application.

IoT Data Collection

Measurement data is sent to the server using an HTTP endpoint:

POST /<device>/save_data

The server validates incoming JSON messages and stores measurement points in the InfluxDB database.

A dedicated Python test client was created to simulate a real IoT device. It generates temperature and humidity measurements and sends them to the server, allowing the complete system to be tested without physical hardware.

Real-Time Communication with WebSocket

The web interface communicates with the backend using WebSocket connections.

Each connected client receives a unique identifier and two dedicated message queues:

• in – messages received from the client
• out – responses waiting to be sent back

Incoming requests are processed by a background processing_thread.

The communication layer supports several operations:

• get_data – retrieves measurement data
• get_mean – calculates average values
• get_max – retrieves maximum values
• get_min – retrieves minimum values

This approach separates WebSocket communication from database processing and allows multiple client connections to be handled independently.

Time-Series Data with InfluxDB

Measurement data is stored using InfluxDB, a database designed for time-series data.

The database layer provides functions for storing measurements, retrieving data for selected time ranges, calculating average values, and finding minimum and maximum values.

This makes it possible to efficiently store and analyze measurements collected from IoT devices over time.

Data Visualization

The project includes a web-based interface for interacting with the collected data.

The user can select an IoT device, define a time range, display temperature and humidity measurements, calculate average, minimum and maximum values, and visualize measurements on charts.

Communication between the interface and the server is handled in real time using WebSocket.

Message Processing

One of the more interesting parts of the project is the internal message processing mechanism.

Each WebSocket connection is assigned individual input and output queues. A dedicated background thread periodically processes incoming requests, performs the appropriate database operations, and places the results in the corresponding output queue.

This allowed me to experiment with multi-client communication, message queues, background processing, and separation of communication logic from data processing.

Technologies

Backend: Python, Flask
Communication: HTTP, WebSocket, JSON
Database: InfluxDB
Frontend: HTML, JavaScript
Architecture: Client–Server, message queues, background processing
Application: IoT data acquisition and visualization

What I Learned

BeeexAPI gave me practical experience in designing a complete communication path between IoT devices and a server application.

The project allowed me to work with HTTP-based communication between IoT devices and a backend, real-time WebSocket communication, time-series databases, message validation and error handling, background data processing, communication between multiple software components, and visualization of measurement data.

It was also an opportunity to look at an IoT system from a broader perspective, not only from the embedded device side, but also at the infrastructure required to receive, process, store, and present data generated by embedded devices.
