SmartHome Controller

Embedded Smart Home controller based on the Microchip PIC-IoT WG platform, WiFi, MQTT and Home Assistant

SmartHome Controller is an embedded system developed to connect physical sensors and user controls with a Home Assistant-based Smart Home environment.

The project combines embedded C development, sensor acquisition, wireless communication and home automation. The controller measures environmental conditions, detects user input through physical buttons and communicates with a local Smart Home server over WiFi using the MQTT protocol.

The project was developed during the 2023/2024 academic year as part of the Microelectronics in Technology and Medicine (MTM) programme at AGH University of Krakow.

Hardware Platform

The project is based on the Microchip PIC-IoT WG Development Board (AC164164), an embedded IoT development platform built around the PIC24FJ128GA705 microcontroller.

The board integrates an ATWINC1510 WiFi controller, an MCP9808 temperature sensor, an ambient light sensor and physical buttons, providing the hardware required to build a complete network-connected embedded application.

Microchip PIC-IoT WG Development Board (AC164164).

System Overview

The embedded controller acts as a bridge between physical sensors and the Home Assistant environment.

The device collects:

  • temperature measurements,
  • ambient light intensity,
  • states and actions of two physical buttons.

The collected information is transmitted wirelessly to a local Home Assistant server using MQTT.

Microcontroller → Sensors / Buttons → WiFi → MQTT → Home Assistant → Smart Home Devices

Overview of the SmartHome Controller system architecture.

Environmental Monitoring

The controller continuously acquires environmental data using sensors integrated into the development platform.

Temperature is measured using an MCP9808 digital temperature sensor, while ambient light intensity is acquired through the microcontroller's ADC.

The measurements are sent to Home Assistant, allowing current environmental conditions to be displayed directly on the Smart Home dashboard.

Physical Smart Home Controller

In addition to environmental monitoring, the device can be used as a physical controller for Smart Home devices.

Two onboard buttons support multiple types of interaction, including:

  • single press,
  • double press,
  • button hold.

This makes it possible to assign several independent Smart Home actions to only two physical buttons.

Depending on the detected action, the Home Assistant server can trigger different automations, such as switching WiFi-connected lights on or off or controlling a robotic vacuum cleaner.

MQTT and WiFi Communication

Wireless communication is handled over WiFi, while MQTT provides the communication layer between the embedded controller and the Smart Home server.

My main responsibility in the project was the development of the network communication layer, including WiFi connectivity and MQTT communication between the embedded device and the Home Assistant server.

I developed the communication module responsible for establishing and maintaining the network connection, managing MQTT connectivity and publishing data generated by the controller.

The communication logic was separated from the main application functionality and implemented using a state-machine-based approach, allowing the firmware to manage different stages of network and MQTT connectivity in a structured way.

This part of the project gave me practical experience with implementing network communication on an embedded platform and integrating a microcontroller-based device with an external IoT system using MQTT.

Home Assistant Integration

The Smart Home server was built around Home Assistant running on a Fujitsu terminal with Debian Linux.

The environment integrates:

  • Home Assistant,
  • MQTT Broker,
  • Node-RED,
  • Docker,
  • TuyaLocal-compatible Smart Home devices.

Node-RED processes information received from the embedded controller and translates button actions into Smart Home commands.

Sensor readings can be presented directly on the Home Assistant dashboard, while physical buttons can be mapped to actions performed by other devices connected to the system.

Project Architecture

The project was designed as a complete embedded-to-server solution. The microcontroller handles physical inputs and sensor measurements, while the communication layer provides connectivity with the Smart Home infrastructure.

MQTT acts as the interface between the embedded device and Home Assistant, allowing the hardware controller to remain independent from the higher-level automation logic.
