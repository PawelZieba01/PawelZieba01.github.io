FPGA Battleships

Paweł Zięba August 31, 2026

FPGA Battleships is a hardware implementation of the classic two-player Battleships game using two FPGA development boards.

The project was developed as part of the Digital Electronics Systems 2 course during the 4th semester of Microelectronics in Technology and Medicine.

The complete game logic, VGA output, board state management, user interaction, and communication between players are implemented in FPGA logic.

The Idea

The idea behind FPGA Battleships was to create a hardware version of the classic game in which the complete history of shots is stored and displayed throughout the game.

The system consists of two Basys 3 FPGA boards, one for each player.

Each player places ten ships on their own board. After completing the placement phase, the players can start the game and take turns selecting fields on the opponent's grid.

After each shot, the FPGA boards store the result and update the corresponding fields displayed on the monitors.

The game continues until one player's ship counter reaches zero.

Game Logic

The main game logic is implemented using a Finite State Machine.

The FSM controls the different stages of the game, including ship placement, starting the game, player turns, shooting, board updates, and the end-game condition.

A separate player_ctrl module monitors user interaction, including mouse position and interaction with objects displayed on the screen.

The current state of both game boards is stored in dedicated memory blocks and accessed by the main state machine and the VGA pipeline.

FPGA-to-FPGA Communication

One of the most interesting parts of the project is direct communication between two Basys 3 FPGA boards.

Communication is based on two parallel 8-bit buses used to exchange grid addresses.

Additional control signals are used to indicate system readiness and shooting actions.

The architecture is symmetrical. Both FPGA boards run the same design and are connected using corresponding input and output signals.

Their behavior at any given moment depends on the current state of their internal game logic.

VGA Output

Each FPGA board generates a VGA signal for its own monitor.

The VGA pipeline reads the current state of the game boards from memory and displays the appropriate information on the screen.

Different colors represent the state of individual grid fields:

• Green – player's ship
• Blue – missed shot
• White – empty field
• Red – hit ship

Because the board state is stored in memory, the history of previous shots remains visible throughout the game.

Seven-Segment Display

The built-in seven-segment display on the Basys 3 board is used to display the ship counters.

During the ship placement phase, the player can see how many ships are still left to place.

During the game, the display provides information about the remaining ships.

Clock Architecture

The project uses two clock frequencies generated by the clk_wiz_0 module.

The 65 MHz clock is used for the VGA pipeline and seven-segment display.

The 10 MHz clock is used for the main state machine, control logic, and communication with the second Basys 3 board.

This separates the video-related logic from the main game and communication logic.

Technologies

FPGA platform: Digilent Basys 3
HDL: Verilog
FPGA development: Xilinx Vivado
Digital design: RTL, Finite State Machines
Video output: VGA
Communication: Parallel FPGA-to-FPGA interface
User interface: Mouse, VGA display, seven-segment display
Clock frequencies: 65 MHz / 10 MHz

What I Learned

This project gave me practical experience in designing a larger digital system implemented entirely in FPGA logic.

It allowed me to work with RTL design, Finite State Machines, VGA signal generation, memory-based state management, user interaction, multiple clock frequencies, and direct communication between two FPGA boards.

An especially interesting part of the project was designing a symmetrical system in which two FPGA boards run the same design while communicating directly and maintaining their own game state.

The project also provided experience in integrating multiple independent hardware modules into a complete working system.
